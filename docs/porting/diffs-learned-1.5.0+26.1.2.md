# Diffs learned — 1.5.0+26.1.2 (thread 1 of 4)

Draft for appending to the next port thread's kickoff (`kickoff-1.5-1.21.11.md`) per this campaign's
Phase-9 closeout step. Written here rather than in the protected `Latitude-1.5-26.2` checkout — copy
forward when that kickoff is created.

## Real bugs found and fixed, not port-specific — worth checking on every remaining target

1. **Structure siting and `/locate structure` disagree about which biome is real.**
   `ServerLevel` builds its `StructureCheck` from `ChunkGenerator.getBiomeSource()` — which
   `ChunkGeneratorBiomeSourceMixin` overrides to the Latitude-repainted wrapper — but
   `ChunkGenerator.tryGenerateStructure` reads the raw `biomeSource` **field** directly (confirmed via
   `javap -c`, not the getter). Vanilla's structure *prediction* therefore judges the repainted biome
   while actual *generation* judges the raw one. This single split explains two opposite-looking
   symptoms: `/locate` promising a structure that never generates, and a structure generating on raw
   desert that Latitude then repaints to snow. Fix: substitute the Latitude-wrapped biome source into
   the existing `Structure.generate` `@WrapOperation` before calling `original.call(...)`, so siting
   judges the same final biome the player stands in. Check whether this port's copy of
   `ExtremePolarVillageStartGuardMixin` (or equivalent) already does this before re-deriving it.

2. **`/locate structure` itself is architecturally blind to Latitude** — same class of gap already
   fixed for `/locate biome` (`LocateCommandMixin` → `LatitudeBiomeLocateService`), never extended to
   structures until this thread. Vanilla's search is a hardcoded 100-ring sweep with zero world-border
   awareness, tested against the raw biome. `LatitudeStructureLocateService` (new this thread) mirrors
   vanilla's own `RandomSpreadStructurePlacement.getPotentialStructureChunk` ring algorithm, bounded to
   `WorldBorder.isWithinBounds`, tested against the repainted biome only (once fix #1 lands, that's the
   sole condition that matters). Cheap enough to run synchronously — no tick-slicing needed, unlike the
   biome locate service's exhaustive block scan.

3. **Placement-time structure guards are a proven anti-pattern — don't reintroduce one.** A mixin that
   cancels `StructureStart.placeInChunk` runs *after* `tryGenerateStructure` already calls
   `StructureManager.setStartForStructure`, so the cancelled structure is still stored, serialized, and
   reports as existing after a world reload, with no blocks. 26.2 tried exactly this
   (`StructureBiomeMatchGuardMixin`, `78a09e2d`) and consolidated it away into a single generation-time
   guard for this reason — the reasoning survives in `VillageLatitudePolicyTest`'s
   `locatableStartsAfterReload` assertions even though the removal commit itself was an unexplained
   squash. If a future target's `tools/verify_structure_climate_guard.py` (or equivalent) still expects
   the placement-time mixin, that verifier is checking for the rejected design — retire it rather than
   satisfy it.

4. **Spawn-zone targets must be derived from the canonical band, never hand-picked.**
   `LatitudeMath.spawnFracForZoneKey` had `SUBTROPICAL -> 0.40` hardcoded — one degree past its own
   23.5°–35° band, so every Subtropical spawn landed in Temperate. 100% reproducible, not an edge case.
   26.2's `ddb531b4` fixed it with `centerFrac(band) = (band.lowDeg() + band.highDeg()) * 0.5 / 90.0`;
   ported here. Check any zone/band fraction table on sight for values that were never verified against
   the band they claim to represent — this class of bug hides easily because it compiles and "looks"
   reasonable.

## Tooling / technique notes

- **A headless dedicated server doesn't need the Fabric Installer.** Loom's dev classpath (the
  `-classpath` line from `build/loom-cache/argFiles/runClient`, generated by briefly running
  `./gradlew runClient` and killing it once the file appears) already contains the merged client+server
  jar and every dependency. Launch `net.fabricmc.loader.impl.launch.knot.KnotServer` directly against
  that same classpath with `-Dfabric.gameDir=<throwaway dir>` — faster and simpler than installing a
  separate server jar, and fully isolated from any shared dev-client window.
- **Region-file heightmaps use padded, not no-padding, long packing** in this codebase's Minecraft
  version — `floor(64/bits)` values per long, remainder bits wasted (confirmed by array length: 37
  longs for 256 entries at 9 bits is `ceil(256/7)`, not the no-padding scheme's `ceil(256*9/64)=36`).
  Block-state packing switched to no-padding in 1.16; heightmap arrays evidently didn't. Verify this
  assumption again on a different target before trusting it — Minecraft/mapping versions can differ.
- **A headless server with zero connected players does not tick entity gravity**, even in forceloaded
  chunks — summoned armor stands/items just sit at their spawn Y indefinitely. Chunk *generation*
  (including structure placement) still happens fine, since that's part of generation itself, not
  simulation. Don't waste time on entity-physics height probes; read the heightmap NBT directly.
- **Building a different tag in an isolated throwaway `git worktree`** (`git worktree add -b <temp>
  <path> <tag>`, remove both after use) is a clean, safe way to get a comparison baseline without ever
  touching a protected checkout.
- **The dev/tools package split needs two checks, not one**: the structural check
  (`tools/verify_phase6_dev_tooling.py`, no args) proves the source-level convention holds, but only
  the jar-level check (`--public-jar build/libs/<jar>`) proves nothing under `dev/` actually leaked into
  a real packaged build. Run both before release, not just the structural one.

## Process lessons

- A shared dev-client window can be someone else's live session, not an idle test instance — confirm
  before sending automated input, the same discipline as confirming a save directory isn't someone
  else's live evidence before `rm -rf`.
- When a live report doesn't match a fix that should have addressed it, measure before re-theorizing —
  add diagnostic counters, reproduce headlessly, and let the numbers name the actual failing gate rather
  than guessing at a second cause.
